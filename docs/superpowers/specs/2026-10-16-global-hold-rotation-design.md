# Global service order and Hold rotation

User-confirmed rules: a computer's position 1 outranks every computer's position 2. Equal positions rotate using each service's Hold. All computers remain visible; only owned services are editable. Add real service details and operational information, not synthetic registrations.

Use explicit per-computer order as global tiers (smaller position is higher). Retain the existing urgent-message safety lane and sticky urgent action semantics. Ordinary higher-tier work immediately preempts lower-tier work across computers. Preemption never ends or republishes an occurrence. Equal-tier services receive visible-time turns of their own Hold, including source-controlled agents. Each service keeps a persisted remaining turn and FIFO ticket, separate from occurrence lifetime. On turn exhaustion with an equal-tier peer, move that service to the tail. Content updates, heartbeats, native refreshes and object eviction must not reset a turn. Higher-tier interruptions preserve the unfinished lower-tier turn and ticket so it resumes when the higher tier clears. A single ready source does not switch to itself or spin alarms. Finite messages still end after their original cumulative visible budget; source-controlled messages stay alive across turns until source end/expiry/pause.

Rotation time starts after successful native display confirmation and entrance, consumes only confirmed healthy time, and pauses while preempted or offline. Arm Durable Object alarms for the next relevant turn boundary only when an equal-tier peer is ready. Snapshot queue/progress/ETA must describe the same next selection as the scheduler; a lower tier behind an ongoing higher-tier source remains unresolved. Scope-filtered producer snapshots must not reveal peer service identities or content.

Service details use existing shadcn/Tailwind surfaces: global tier, collector/template, full registration ID, computer, enabled state, source online/last heartbeat, current display/queue count and preview/button capabilities. Add persisted lastHeartbeatAt for idle registered services; do not label unknown sources connected from device health. Keep the single-editor desktop/mobile layout, Number Flow readouts and owner-only mutation boundaries.

Validate cross-computer preemption/resume, equal-tier sources with unequal Hold, native confirmation and entrance, interrupted turns, finite lifetime preservation, no competitor/no-alarm spin, stale ACK/heartbeat/update/eviction, migration and owned service details. Review before merging; use native Cloudflare Builds and verify the real DO protocol after deployment propagation. Do not re-register services or touch paused FPS work.

User additions: Agent status and approval/question prompts are independent registered services. The Mac routes all live waiting turns to an explicit agent-notifier registration, preserves each task identity and renders other working tasks through the status service. Missing, same-ID or wrong-template routing fails with setup_required_agent_notifier. Add POST /api/withdraw for scoped, idempotent permanent removal of exact occurrences, backed by tombstones and a durable local outbox; active withdrawal immediately returns control to the next eligible service.
