# Control plane protocol v1

All timestamps are UTC milliseconds. JSON endpoints are same-origin `/api`; no arbitrary BUSY proxy exists. Errors are `{error:code}`. 409 is a revision/stale target conflict; 413 is a bounded capacity rejection. Static assets are public, API bodies are `Cache-Control:no-store`. Native firmware draw priority is fixed 51, independent of per-computer service order. This is above the legacy observer at 50 and still yields to higher-priority native applications.

## Authentication

`POST /api/session {token}` verifies the token against BUSY `GET /status`, requires `device.serial_number`, derives opaque deviceId (SHA256 serial), encrypts the token with Worker `TOKEN_ENCRYPTION_KEY` (64 hex AES256), and sets Secure/HttpOnly/SameSite=Strict cookie. No device ID supplied by clients is trusted for login. `GET /api/session` returns `{deviceId}`; `DELETE /api/session` revokes this session. `SESSION_SIGNING_KEY` is a separate random Worker secret. Browser mutations require matching Origin and JSON. Cookie-authenticated writes must send `X-Busy-Device` with the deviceId currently rendered by that tab; it is checked against the verified session before any DO operation. Missing binding returns403 `DEVICE_BINDING_REQUIRED`; cross-tab cookie/device mismatch returns409 `DEVICE_SESSION_CHANGED`. Login is excluded. Logout and authenticated reads may omit the binding, but any supplied binding must match. Bearer publishers already encode their authorized device and are unaffected. New sessions expire after 30 days. Cookie Max-Age and the signed and stored expiry use the same duration; reads do not extend it. Sign out revokes the session immediately. A transient session-check failure must offer retry, not require another token. BUSY response bodies/tokens are never exposed.

A device-key browser session is monitoring-only until paired. `GET /api/session` also returns `computerId: string|null`. A local preference never grants management access.

`POST /api/computers/enrollment {}` creates a one-use five-minute ticket `enroll.deviceId.computerId.secret`. An unpaired browser may hold one pending ticket. `POST /api/computers/enroll {managementSecret}` uses that ticket as its Bearer, without cookies. The client must generate and store its management secret **before** the request. The server stores only a hash and returns `{computerId,enrolled:true}`. A pending retry probes the saved computer key first; only a true not-found404 permits the original grant attempt again. Invalid/revoked keys are terminal.

Computer credential format: `deviceId.c.computerId.randomSecret`. `GET /api/computer` verifies it and returns that computer’s service registrations and config revision. `POST /api/computers/claim {proofs:{serviceId:legacyCredential,...},managementSecret}` uses one existing publisher Bearer and requires the complete live legacy credential set for the same computer. It claims its previously migrated order once, without changing item namespaces or exposing keys.

`POST /api/computers/pairing {}` requires the computer Bearer and returns a one-use five-minute `pair.deviceId.secret` code. The browser sends it to `POST /api/session/computer {code}`. The server binds that live browser session to the computer. Sign out before binding another computer. Enrollment/claim and pairing are bounded; codes are hashed and expired by alarms.

`POST /api/services {id,name,template:'agent'|'notifier'|'custom',priorityGroup?:'interception'|'follow-queue'|'dispensable',expectedRevision,config?:{enabled,allowInput,allowPreview,visibleMs,heartbeatMs}}` requires a paired owner browser or computer Bearer. Its computer is derived from authenticated authority; an explicitly supplied different `computerId` is forbidden. `PATCH /api/services/:id {expectedRevision,config}`, `POST /api/services/:id/revoke {expectedRevision}`, `POST /api/services/:id/credential {expectedRevision}`, and `POST /api/services/:id/remove {expectedRevision}` require the same ownership proof. Unresolved actions block removal. Config writes use `snapshot.configRevision`. Legacy publisher keys cannot manage registrations. All identifiers match `[A-Za-z0-9_-]{1,64}` excluding prototype keys.

Registration returns a legacy single-service credential, stable epoch, expiry and snapshot. Epochs expire after30days; credential replacement rotates the epoch and ends old items. Existing single-service credentials remain publisher-only and scoped to their one service. Computer publishing requires an explicit owned `X-Busy-Service` header or `serviceId` body; conflicting targets are rejected. Assets, heartbeat, end/withdraw, actions, input and preview all enforce that target. One computer key may publish any app label/content to any owned ID; the Mac owns source routing, not the cloud.

`POST /api/services/order {groups:{interception:[ids...],"follow-queue":[ids...],dispensable:[ids...]},expectedRevision}` atomically sets group membership for the authenticated computer's services. Array positions have no scheduling meaning and do not change stored display order. All three keys and exactly all owned services are required. Duplicate, missing, unknown or foreign IDs are rejected before mutation. Other computers remain visible and immutable. The legacy `{serviceIds,expectedRevision}` form still accepts a complete owned permutation and preserves existing groups. Legacy service order is display metadata only. Legacy numeric priorities are inert.

Every service exposes `priorityGroup`: **Interception > Follow queue > Dispensable** globally, independently of local row position. Registration accepts an explicit group; agents default to Dispensable and other templates to Follow queue. A one-time migration fills missing fields and applies the owner's approved existing-service assignments; later startup never resets a user's group choice.

Interception immediately preempts lower groups. Follow queue work waits for the active same-group occurrence to complete; a source-ended occurrence remains until its host ends it. All services in a group have equal priority, regardless of computer or display order. Interception and Follow queue use occurrence arrival order after the current occurrence completes. Dispensable background work rotates all eligible services by their confirmed Hold, including services on the same computer. Higher groups interrupt and preserve the original occurrence, remaining lifetime and turn. Source urgency does not escape its registered group. Action semantics and native-confirmed queue/coverage proofs still apply to urgent messages waiting behind a healthy controller. Entry and unconfirmed time never consume visible budgets. Content updates, heartbeats and object restart do not restart source or finite lifetimes.

Legacy stored `exit` and `snoozeMs` config fields are retained for old clients. The manager does not edit them. A declared per-message `exit` takes precedence over the legacy service override; omitted `exit` retains legacy inference. `snoozeMs` no longer schedules replay.

## Producer

`POST /api/publish`:

```json
{
  "instanceId": "mac-a",
  "epoch": "issued-stable-epoch",
  "itemId": "stable-occurrence-uuid",
  "version": 1,
  "firstRecognizedAt": 1792000000000,
  "kind": "event",
  "exit": "finite",
  "level": "attention",
  "groupKey": "optional-source-group",
  "app": "Mail",
  "title": "Queue title",
  "detail": "Queue detail",
  "validUntil": 1792000060000,
  "actionKeys": ["primary"],
  "businessId": "optional-source-id",
  "scene": {
    "entryDurationMs": 1200,
    "commands": [
      {
        "offsetMs": 0,
        "elements": [
          {
            "id": "icon",
            "type": "animation",
            "assetHash": "SHA256",
            "loop": true
          }
        ]
      },
      {
        "offsetMs": 1200,
        "elements": [
          { "id": "label", "type": "text", "text": "Hello", "font": "small" }
        ]
      }
    ]
  }
}
```

`exit` is `finite|source` and is declared by the publisher for each new occurrence. `finite` uses the service Hold (`visibleMs`); `source` remains until the publisher ends it, subject to the same validity/heartbeat/epoch fences. The first accepted occurrence fixes its lifetime; later content versions do not restart or change it. Old publishers may omit `exit`: urgent/agent defaults to source, other messages default to finite, with the legacy service override retained. A finite condition completes instead of returning automatically. Persisted old snoozed occurrences are completed on the next tick. Heartbeats and old item IDs cannot revive completed work; the host chooses when to issue a new occurrence with a new itemId.

`kind` is `event|condition|agent`; `level` is `urgent|attention|info`. `version` monotonically increases; equal version retransmission is idempotent and cannot change body. Identity is JSON `[serviceId,instanceId,itemId]`, exposed as `itemKey`. Scene accepts optional `ledColor` as `#RRGGBBAA`. Scene is complete recoverable entrance, <=32 ordered commands, offsets 0..10000ms, <=64 elements total; at least one offset0 command. All element IDs are namespace-local. Asset references use `assetHash` replacing native `path`; producer-supplied native paths/stock paths/timeout/display_until/application_name are rejected. Allowed native elements: text/image/animation/countdown/rectangle/xpmbitmap, plus documented rendering properties. Assets and text bounded. Optional `app` is a plain nonempty string of at most64 characters (no control characters or whitespace-only value); older items omit it. App metadata does not alter recognition/receipt times, identity or queue order. Producer title/detail max 256/2048 chars, total body max 128KiB, per-device 256 live items/2MiB presentation JSON. firstRecognizedAt is immutable, accepted within 5m backend receive time; otherwise receive time is used and timeReliable=false. validity maximum 24h; heartbeats renew only source liveness, never visible duration or completed occurrence. Items cannot outlive their epoch, heartbeat timeout or validity.

`POST /api/heartbeat {instanceId,epoch,itemIds:[...],validUntil}` refreshes matching existing items only, returns snapshot + item results (including tombstones); never creates/revives. `POST /api/end {instanceId,epoch,itemId,version}` ends matching occurrence with monotonic version tombstone. Version and epoch checks reject late traffic even after body cleanup. Tombstones contain identity/version/epoch/reason only, expire with epoch; capacity rejects new work rather than evicting replay protection. New occurrence needs new itemId. Heartbeats also set service-specific `lastHeartbeatAt`, including empty idle heartbeats. Unknown legacy sources remain unknown until they check in; device health is not source connectivity.

`POST /api/withdraw {instanceId,epoch,itemId,version}` uses the same authenticated owned-service target as publish. It permanently withdraws that exact waiting, paused, preempted or displaying occurrence, records a `withdrawn` tombstone and immediately selects the next eligible item. Retrying is idempotent. An unknown item is fenced too, so a delayed publish cannot resurrect it. `version` must be at least the current live version. A fresh notification needs a fresh `itemId`; the host chooses when. `/api/end` remains source resolution (`resolved`). Neither endpoint can operate on another service's namespace without its authority.

`playback` describes a Dispensable service turn when a peer is ready, otherwise the finite visible lifetime (or an unbounded source). `lifetime` separately reports cumulative finite budget; source lifetime stays null. Both run only under matching healthy native confirmation and stop at its expiry. Background peers can have turn ETAs. Work behind an unresolved source or higher group reports `await-resolution`; the server does not invent a completion time for source-ended queued work. Turn records stay internal and bounded by live registrations.

`POST /api/update {instanceId,epoch,itemId,version,generation,elements:[...],scene?:Scene}` applies native motion/content update only to the current selected matching generation. When supplied, the validated complete `scene` replaces recovery state verbatim; `elements` remains only the immediate native draw delta and is not merged into that scene. This lets transient outgoing fade masks and numeric rolls stay out of restored scenes. Without `scene`, matching elements are merged into recovery as before. Both delta and recovery asset references require service ownership. Exact same-version retries bind both delta and optional recovery scene; conflicting retries return409. ACKed native values are persisted separately from recovery, and diffing projects pending generation-bound clear/draw intents over them. Opaque-to-clear mask deltas and same-owner full-publish corrections therefore reach the device without resending unchanged scrolling text. Native metadata is bounded to128live element IDs/1MiB and expires with actual native TTL; acknowledged transient asset hashes keep their device slots pinned through that TTL, independently of recovery membership. Native animation updates preserve IDs and playback; omitted or unchanged text is not resent. Equal-version same-content update retries are idempotent. Element type transitions delete only owned element IDs before replacement. The acknowledged current representative content version advances its frozen admission; unacknowledged later content at finite expiry reenters once with zero remaining lifetime, then completes after entry, without resetting the original visible budget. New group member identities remain excluded from an older admission. A full same-item version publish replaces recovery scene, changes current elements without restarting entrance; scheduler preemption/resume creates a new generation and replays complete entrance using latest scene.

`POST /api/assets {hash,type:'png'|'gif'|'webp'|'anim',data:'base64'}` content hash verified. <=256KiB per asset, 4MiB/64 files cloud cache per device; bounded global device slots 16/2MiB. Unreferenced cache entries are LRU reclaimed; live scenes and pending commands pin cloud hashes, playing/pending command references pin device slots. Capacity failures are explicit. Uploaded assets are service-owned; hashes may be shared by repeated upload, never exposed in snapshots. Unused cloud content expires after1h. Occupied device filenames and extensions are immutable. Images retain same-suffix allocation. Supported bicycle0 animation content may reuse any unpinned existing filename without changing its suffix: firmware opens the animation by its header, not extension. Image requirements reserve first so flexible animations cannot consume their only compatible filenames. File count and byte limits remain unchanged; no alternate-extension file is created. Device filename is backend assigned `slot-N.ext` in `busy-control` namespace. No direct storage paths accepted.

## Shared service motion

### Prepared scene admission

Scene accepts optional `entryLeadMs`, exactly `0` or `200` and no greater than `entryDurationMs`. Omission or0 selects the legacy transition below. A publisher opting into200 must prefix each first-command non-loop animation with200ms of black, add200 to subsequent command offsets and the entrance duration, and preserve text's original timing relative to reveal (including first-command native text scroll delay). This metadata is a publisher timing contract; the backend does not rewrite arbitrary animation bytes. The complete recoverable source scene retains its logical IDs and original entrance.

For `entryLeadMs:200`, the old view stays visible while all incoming scene assets and two internal black-hold animations are reserved and uploaded. There is no preceding outgoing fade or host black-hold fence. One native handoff draw neutralizes obsolete text, hides obsolete images/animations (or moves countdown/rectangle widgets off-canvas), starts the incoming first command, and places fresh72x16/160x80 black masks at Z255. Each mask is an RLE `bicycle0` animation at50FPS: ten black frames followed by a retained transparent frame, with `default`, `hold` and `clear` sections. Front688B SHA256 `d2ea65bfdffa8dee7c459552ab48054d296bfc0ad49846bd6b003b0052e0be35`; back5693B SHA256 `75bc573cfb04986187f673acac4cd26fce19670b2f095c9a469909d30f344dac`. These exact assets automatically released both screens in the controlled device probe without a later unmask draw. Asset-frame timing and full service-chain physical timing remain separate evidence.

The two masks become transparent locally after their200ms program; retirement HTTP is not needed to reveal the next scene. Old selective retirements are scheduled no earlier than200ms after the commit ACK, keeping their HTTP/GUI work out of the local black program even when ACK is fast. New masks remain until a later handoff or their bounded native TTL, so a fast retirement DELETE cannot shorten the hold. All prepared scene element IDs receive a generation-specific native mapping used consistently for later commands, updates, renewals and recovery; the publisher's source IDs remain unchanged. Same-occurrence updates do not create another entrance. Generation changes and uncertain writes retain existing stale-target and recovery fences. Visible/Hold budgets still wait for matching entrance and retirement acknowledgements.

Cache64/4MiB,16 immutable filenames/2MiB and32 elements per native draw remain unchanged. Prepared commits conservatively cap the live-ID union at100, matching installed firmware1.2.4; the legacy model's128-ID bound is unchanged. Pending internal mask hashes pin their cache entries/slots before commit. If only the masks cannot fit, the compositor tries one prepared incoming draw without them and records `expectedBlackMs:0`; this is not a successful200ms black transition. If normal incoming content cannot coexist with the pinned old view, or safe same-draw hiding is prevented by native draw-capacity conflicts, it retains the old view and retries with bounded backoff. It does not clear old file-backed widgets to wait for uploads or stage an entrance hidden behind old opaque widgets. The old view's finite native TTL still applies; a blocked device has no indefinite display guarantee.

An empty queue uses a scoped DELETE directly, retaining the previous view until that request applies. It does not introduce a black animation before waiting for network cleanup. Existing priority groups, occurrence leases, registration/configuration and source privacy are unchanged.

### Legacy scenes without a prepared lead

Warm changes of selected occurrence, including natural completion, priority preemption and resume, share one outgoing transition. The compositor targets a200ms fade to black followed by200ms black. Initial/cold admission has no outgoing fade. Visible/Hold budgets pause before the exit and resume only after the incoming entrance and retirement acknowledgements; an exit or entrance never grants display proof. The direct empty-queue DELETE rule above also applies to legacy scenes.

The native fade preuploads public `bicycle0` animation assets, then submits one fade-start draw. Seven local30FPS frames sample a smoothstep opacity curve at t0 through t200ms; there are no per-frame HTTP opacity draws. Pixel alpha samples are1,19,66,128,189,236,255: a slow diagnostic with fresh widget IDs and alpha1 preserved intermediate levels after earlier probes showed only gray-to-black. Those two changes were combined, so the evidence does not isolate a firmware alpha/cache defect; alpha1 is a conservative first-frame choice. Normal-speed and both-display physical evidence remain separate from byte-format and mocked transport tests. Front uses a dedicated72x16 asset and back one160x80 asset. Uniform-pixel RLE reduces these files to526 and4166 bytes respectively; the larger back player is loaded before front. Controlled device capture of these exact assets showed intermediate front levels, full back service-canvas coverage and opacity0 restoration. It does not measure an exact physical200ms interval. After the fade-start acknowledgement, a monotonic200ms fence conservatively assures animation completion, then starts the200ms black hold. Slow HTTP acknowledgement can therefore extend actual black beyond200ms. Wall-clock deadlines wake the Durable Object but never complete either fence. Persisted elapsed progress is a lower bound after eviction: a new object resumes the remaining phase without replaying completed progress.

Candidate changes and source refreshes retain the same motion identity while masks remain opaque, so they cannot continually replay the fade. Once an incoming acknowledgement makes every mask transparent, a later preemption starts a fresh exit for that now-visible view. The dispatcher also checks for an old-generation incoming acknowledgement that proves visibility only after a newer candidate was selected. A same-path section change does not restart a finished firmware player; opacity0 is the unmask mechanism, and each exit uses fresh animation widget IDs so a visible handoff can be preempted and replayed safely. An uncertain sent draw retains the existing full namespace recovery and complete replay, rather than leaving an untrusted opaque mask.

The native200ms/200ms intervals are compositor targets, not exact physical-frame or WAN guarantees. HTTP latency, scheduler wakeup delay, asset-capacity reclamation, retry backoff and object eviction can extend the transition; an offline or blocked device cannot be given a bounded physical display deadline. Internal assets have no producer ownership and obey the existing64-file/4MiB cloud cache limit. The compositor reuses historical unpinned filenames, preserving the16-file/2MiB device budget and immutable filename suffixes. A PNG-only history can carry the same bicycle0 bytes under its original PNG filenames. If two safe animation slots or coexisting incoming capacity are unavailable, the explicit fallback is one opaque XPM draw followed by a200ms black hold; that fallback is a hard cut and does not satisfy smooth200ms fading. The full incoming asset set is preloaded before the fade when slots can coexist; otherwise the acknowledged black masks retain the application during bounded reclamation/upload. At the128-widget limit, transparent old masks are reclaimed first, then only the few outgoing IDs needed for masks; this can remove those widgets early but does not empty the native application.

The compositor globally reserves IDs prefixed `control-service-motion-` and `control-prepared-entry-` and native `z_index:255`; producer scene elements and `/api/update` deltas must use a lower Z and cannot claim those IDs (`COMPOSITOR_LAYER_RESERVED`). Two native animation masks cover the72x16 front and160x80 back application canvases; the legacy capacity fallback uses five XPM masks. Fallback back XPM uses four160x20 strips so every inline element stays below8KiB. Firmware-owned status indicators outside the application canvas remain firmware-controlled.

For ordinary scenes, incoming first content, obsolete scrolling-text blanking and all opacity0 masks are submitted in the same native draw. A delayed selective retirement DELETE therefore cannot hide the whole incoming entrance or leave old high-Z text over it. If the combined draw exceeds32 elements, obsolete text is blanked under opaque masks, the source scene is staged under black, and a bounded unmask draw restarts only `shared-service-entry`. That unmask becomes the first entrance acknowledgement, and subsequent scene offsets start from its acknowledgement. Mask IDs are selectively retired afterward; the application remains populated throughout. A same-item full publish updates stored recovery content but does not replay or cancel the shared entry helper; its original pending completion draw remains scheduled.

### Read-only diagnostics

`GET /api/diagnostics/display` identifies the actual DO implementation as `shared-service-motion-v2-prepared`. It retains up to128 content-free events for one hour. `command_ack`/`command_failed` include `stage:prepare|commit|retire`, `requestMs` for the actual `BusyClient.request` interval, and `preRequestMs` for preceding preparation, alarm scheduling and decryption; legacy `elapsedMs` also includes post-request bookkeeping. These runtime-clock observations are not pixel timestamps. `prepared_handoff` records planned `expectedBlackMs` and `pendingUploads` (zero before a prepared commit), while `motion_fallback` records fixed reasons and quota counts without source content, hashes, credentials or item keys. A prepared plan or successful HTTP ACK does not itself prove physical200ms behavior. Tests use mocked upstream HTTP and controlled monotonic clocks; passing tests are not physical device-frame evidence.

## Snapshots and UI

`GET /api/snapshot`, `GET /api/events` (SSE `event: snapshot`, data full JSON) return current full state, no Last-Event-ID replay. SSE expires/reconnects after 55s; max16 connections and slow consumers closed. All state events use same snapshot revision. Producer must reconnect with Bearer fetch streaming (EventSource cannot set header).

Snapshot fields: `{protocol:1,deviceId,revision,configRevision,generation,health:{status:'unknown'|'healthy'|'blocked'|'offline',confirmedValidUntil,lastSuccessAt},selected:itemKey|null,applying:itemKey|null,displaying:{itemKey,generation,confirmedAt,confirmedValidUntil}|null,computers:[{id,serviceOrder,enrolled}],services:[{id,name,template,priorityGroup,computerId,computerIds?:string[],config,epoch,epochExpiresAt}],items:[{itemKey,serviceId,instanceId,itemId,version,kind,level,groupKey,app?,title,detail,firstRecognizedAt,timeReliable,receivedAt,enqueueSeq,state:'waiting'|'applying'|'displaying'|'preempted'|'paused'|'snoozed',remainingMs,nextEligibleAt,eta:{kind:'estimate'|'await-resolution'|'paused'|'snoozed'|'unknown',at?:number},queueProof?:{revision,itemKey,controller:{itemKey,generation},validUntil}}],groups:[{groupId,representative,memberKeys,level,order}],actions:[{id,requestId,itemKey,serviceId,instanceId,itemId,version,generation,actionKey,businessId,status:'pending'|'running'|'succeeded'|'failed'|'unknown',createdAt,expiresAt}],tombstones:[{itemKey,version,reason}]}`.

Producer sees own service, items, groups, actions and tombstones only. Other-owner confirmation metadata includes opaque itemKey/generation/validity; no other service title/detail/scene/business ID/credential. Items also expose own `actionKeys`, `actionAvailable`, `validUntil`, `lastHeartbeat` and `source:{connected,lastHeartbeat}` to admin/authorized publisher. Frozen admitted group item IDs/versions receive `coverageProof:{revision,itemKey,version,controller:{itemKey,generation},validUntil}` bounded by the actual matching device confirmation. A late unadmitted urgent group member gets waiting queueProof instead of a display claim. queueProof is emitted only for eligible waiting urgent work behind the scheduler-selected, confirmed healthy controller in the same or a higher service group; that controller may be nonurgent. The proof is bounded by actual device confirmation and never claims the queued message was displayed. Repeated snapshots/heartbeat do not extend confirmation. `displaying` means successful API acknowledgment, not pixel readback.

`POST /api/items` (paired owning browser) `{itemKey,operation:'pause'|'resume'|'end',expectedRevision}` uses current snapshot revision. `POST /api/actions {requestId,itemKey,generation,actionKey}` (paired owning browser or owning publisher with instanceId) creates durable action. Only advertised action keys accepted, online source required; expires30s. Producer `POST /api/actions/:id/result {instanceId,status:'running'|'succeeded'|'failed'|'unknown'}`. Repeated result idempotent; terminal transitions reject conflicting result. Timed-out actions become unknown; authoritative late succeeded/failed may resolve unknown, but expired pending actions cannot begin running. Pending actions reappear in every full snapshot; local executor must persist action ID before invoking external side effect. Only succeeded ends original exact item version; stale success never ends newer version/generation or other items. Unknown/failed retain item. Never automatically retry side effects.

`POST /api/input {eventId,instanceId,generation,button:'start_pause'}` (a publisher explicitly granted `config.allowInput:true`; browsers and ordinary publishers are rejected) checks current generation, dedupes event ID. Urgent primary creates action; otherwise atomically tombstones all currently existing nonurgent items (including paused/snoozed) with revision boundary. Urgent survives; same IDs never reappear. 409 stale generation does nothing.

## Live pixel preview

Preview is a read-only LAN Mac → Cloudflare → management browser relay. It never changes the sole native writer or scheduler. A management session may grant a designated bridge `config.allowPreview:true`; the default, including legacy missing fields, is false. Enabled service, current credential, matching unexpired epoch and this explicit capability are required. Ordinary publisher credentials cannot read pixels or preview diagnostics.

`GET /api/preview/publish` upgrades to a WebSocket. Computer credentials additionally require `X-Busy-Service`. Send `Authorization: Bearer <credential>`, `X-Busy-Instance` (normal identifier), and `X-Busy-Epoch` (issued epoch); no cookie or query parameters. Each device has one active publisher lease across all services and instances; a second connection gets409 `PREVIEW_PUBLISHER_EXISTS`. The server sends `{type:"demand",enabled,targetFps:30,streamId,deviceId}` on connection and demand changes. The bridge captures only while enabled. Send `{type:"heartbeat"}` every5s even without demand; frames also count as activity. Fifteen seconds without either releases the publisher lease. A bridge reconnection gets a new opaque streamId and starts a new sequence. The Mac bridge treats exact `PREVIEW_STALE_FRAME`, `PREVIEW_RATE_LIMIT` and `PREVIEW_SEQUENCE` error messages or close reasons as transient: invalidate queued frames, disconnect, then retry with bounded 1–30s backoff and fresh identity verification. Unknown/schema/identity/auth failures remain terminal. Local diagnostics retain only these allowlisted codes in `lastCloudError`.

A frame is `{type:"frame",sequence,capturedAt,pixels}`. Sequence is a positive safe integer strictly increasing within the stream. capturedAt is an integer UTC millisecond source timestamp within ±30s of receipt; this bound does not verify the source clock. Pixels are standard base64 representing exactly3456 RGB bytes:72×16, row-major, RGB channel order, no alpha. Convert device-specific BGR encoding on the Mac before publishing. The complete UTF-8 message is at most6144bytes; binary messages and unknown fields are rejected. Target cadence is30fps with bounded arrival jitter; small excess bursts are dropped/coalesced while sustained flooding closes the publisher. Both frames and heartbeats are subject to message-size and ingress-flood limits. Replay, stale timestamps and malformed payloads produce only `{type:"error",code}` followed by policy close1008. A valid in-flight frame completing after demand stops is dropped with `PREVIEW_NO_DEMAND` while retaining the publisher lease; it does not resume capture or cache pixels. Diagnostics never include frame pixels or source payloads.

`GET /api/preview/frames/<expected-device-id>` is management-session-only SSE. The full URL device must equal the verified session device or409 `DEVICE_SESSION_CHANGED` is returned. No publisher may consume it. SSE `event: preview` carries `{deviceId,connected,serviceId,instanceId,streamId,demand,targetFps:30,acceptedFps,lastFrameAt,lastSequence,viewers,viewerId}`. `event: frame` carries `{deviceId,streamId,sequence,capturedAt,receivedAt,serverNow,pixels,width:72,height:16}`. At emission, serverNow and receivedAt share the relay clock: only frames aged0–2000ms may be emitted. The browser transfers that remaining freshness budget to its own arrival clock, rather than comparing clocks on different machines. Stream/sequence fencing, latest-only relay buffering and the500ms browser playout bound still reject replay and buffered history. This measures relay age and local receipt age, not independently verified end-to-end network latency; source capture time alone is not proof of freshness. During a rolling upgrade, an authenticated old relay status with lastFrameAt/lastSequence establishes receipt/sequence floors. Its existing two-second emission/cache bound is enforced by that relay, while the browser expires accepted frames two seconds after local receipt; frames below either floor or replayed within the stream are rejected. Without that authenticated status metadata, legacy frames retain the former timestamp checks. Network transit time is not independently measured by either format. A disconnected publisher clears the cached frame, arrival metrics and bridge identifiers and notifies writable viewers. Backpressured viewers with an in-flight event are aborted immediately to discard that encoded event; they reconnect and authenticate again. New streams never replay a prior publisher's frame.

Each SSE viewer has an opaque viewerId, owned by its exact management session. Renew every2s using `POST /api/preview/viewer {viewerId,operation:"renew"}`; on document leave/hidden or sign-out send operation `"close"` (keepalive is suitable). Normal cookie mutation Origin and X-Busy-Device fencing apply; publisher credentials cannot renew or close, and another session cannot control the viewer. Missed renewal expires demand within6s even when network cancellation propagation is delayed. SSE closes/reconnects after55s at most, and sooner at session expiry/logout. Max8 viewers per device. Direct cancellation cleans up the viewer; explicit close/lease expiry bounds cleanup across transports. Slow clients receive a bounded in-flight event and the latest available frame, dropping intervening frames instead of growing a queue. Cached frames older than2s are not replayed or emitted. A shown frame that expires stays visible with an explicit “Last preview · Ns ago” label until fresh pixels replace it; stream/device/session changes still clear old pixels. Fifteen seconds without an accepted frame closes the existing lease and reconnects, including an OPEN but silent EventSource. This creates no new local capture loop or status polling. Expiry/close aborts a pending backpressured write; streams with no pending write close gracefully.

`GET /api/preview/status` is management-session-only and returns the same diagnostic fields without viewerId. acceptedFps is the count of accepted frames in the recent rolling second, not a claim of achieved source/display30fps. lastFrameAt is receipt time or null; lastSequence is the latest accepted sequence or null. No active publisher yields connected:false and null bridge identifiers. Config changes, credential rotation/revocation, disablement, logout and expiry revalidate active transports. Authority is cached as session/service capability/credential/epoch expiry metadata and refreshed on durable saves; the per-frame path checks current time without loading full state. Only the latest frame is retained in ephemeral relay memory. No pixels enter SQLite, audit records or logs. The public Worker authenticates each request, forwards a sanitized fixed internal preview path, and the DO rechecks current stored authority before opening the transport.

## Operational bounds

Commands are durable before HTTP. One sequential dispatcher per device checks generation before each next write, fixed 8s HTTP timeout, no redirected requests. DO alarm retries failed commands with bounded backoff, deducts elapsed visible time and recovers uncertain in-flight state by clearing platform namespace and replaying current complete scene. Acknowledged commands are not resent on heartbeat/restart. Finite visible time starts after all entrance writes acknowledge and entry delay completes; preemption pauses it. Finite messages default to10s visible, then complete. There is no automatic condition replay; the host decides when to send a new occurrence. Legacy urgent messages default to source exit. Each acknowledged element retains its conservative send-time TTL expiry. Text and widgets renew independently15s before their earliest actual expiry only when the intended visible end still needs them; short finite text is sent once with remaining+entry+margin TTL (max60s), even when entry delays the final acknowledgment. Steady renewal and same-item full-publish replacements use serialized batches of at most32elements per BUSY draw. Only acknowledgment of every chunk refreshes confirmation, including selective-clear-only replacements; a queued or failed clear cannot advance the admitted content version. Metadata-only replacements bind to an identical still-pending native batch instead of treating it as already accepted. Confirmation remains bounded by the earliest current element expiry; a stale successful prefix after a failed/late suffix cannot establish a proof, and the next alarm reconstructs a complete fresh bounded renewal. Browser close does not stop alarms. No production device writes/deployment are part of automated tests.

A full namespace clear can return400 before the namespace has drawn on real firmware. For that exact payload-free clear only, the backend can draw one transparent1px widget with a one-second timeout and retry the original clear once. The sequence shares one eight-second deadline and rechecks generation before each native write. Only the final clear acknowledgment succeeds the command. Selective clears never bootstrap or widen their scope; failed bootstrap/final clear remains a failure.

### Remove a retired registration

`POST /api/services/:id/remove` accepts `{ "expectedRevision": number }`.
A device-bound management session is required. The operation checks the config
revision and refuses services with pending, running, or unknown local actions.
It ends that service's occurrences, invalidates publisher access by removing the
registration, and reschedules the display. Other registrations are unchanged.
Occurrence tombstones remain until their normal expiry. Register a replacement
with a fresh service ID before removing the retired registration.
